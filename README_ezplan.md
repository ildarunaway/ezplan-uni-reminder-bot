# ezplanbot — Telegram-бот для планирования учебных задач

**ezplanbot** — персональный Telegram-планировщик для студентов: помогает учитывать задания по предметам, следить за дедлайнами и получать напоминания. Проект сочетает пользовательские сценарии в Telegram, хранение данных в SQLite и фоновую обработку уведомлений.

> **Проектное портфолио:** разработан как собственный учебный продукт с применением AI-assisted development. Акцент — на постановке задач, проектировании пользовательских сценариев, интеграции хранилища, тестировании и развёртывании.

## Возможности

- **Учёт предметов:** создание и управление списком учебных дисциплин.
- **Планирование заданий:** добавление работ с типом, названием и сроком сдачи; поддержка нескольких заданий за один сценарий ввода.
- **Управление статусами:** активные и выполненные задачи, просмотр просроченных работ, изменение сроков и редактирование записей.
- **Сводки и статистика:** обзор задач по предметам и типам, подсчёт выполненных, активных и просроченных работ.
- **Напоминания:** периодические дайджесты, настройки частоты и времени уведомлений, сообщения о ближайших дедлайнах.
- **Сохранность данных:** задания и настройки сохраняются в SQLite между перезапусками приложения при использовании постоянного дискового хранилища.

## Технологии

| Компонент | Технология |
| --- | --- |
| Язык | Python |
| Telegram-интерфейс | aiogram 3 |
| База данных | SQLite + aiosqlite |
| Планировщик | APScheduler |
| Конфигурация | python-dotenv, переменные окружения |
| Запуск | Long polling; возможен запуск на удалённом сервере |

```text
Пользователь в Telegram
         │
         ▼
 Telegram Bot API
         │
         ▼
 main.py ─────► keyboards.py
   │                (кнопки и меню)
   ▼
 services.py
   │
   ▼
 db.py ───────► SQLite (файл базы данных)
   ▲
   │
 scheduler.py ─► плановая проверка и отправка напоминаний
```

**Хранение данных.** В проекте используется SQLite: база представляет собой файл, путь к которому задаётся через `DATABASE_PATH`. Если бот запускается на сервере, для сохранения данных после пересборок и обновлений нужно использовать постоянный каталог или подключённый том. Это **не отдельный облачный SQL-сервер**.

## Быстрый запуск

**Требования:** Python 3.10+ и токен Telegram-бота, полученный у [@BotFather](https://t.me/BotFather).

1. Клонируйте репозиторий и перейдите в каталог проекта:

   ```bash
   git clone https://github.com/ildarunaway/ezplan-uni-reminder-bot.git
   cd ezplan-uni-reminder-bot
   ```

2. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Linux/macOS
   # .venv\Scripts\activate   # Windows PowerShell
   pip install -r requirements.txt
   ```

3. Создайте файл `.env` на основе `.env.example` и настройте переменные:

   ```env
   BOT_TOKEN=your_telegram_bot_token
   DATABASE_PATH=./data/bot.db
   DEFAULT_TIMEZONE=Europe/Moscow
   ADMIN_ID=
   ```

   Для локального запуска выбран относительный путь к файлу SQLite; в `.env.example` репозитория указан серверный путь `/data/bot.db`.

4. Запустите бота:

   ```bash
   python main.py
   ```

5. Откройте бота в Telegram и отправьте команду `/start`.

> Не публикуйте настоящий токен в GitHub. Добавьте `.env` и файлы базы данных (`*.db`, `*.db-wal`, `*.db-shm`) в `.gitignore`, если этих правил ещё нет.

## Структура проекта

```text
main.py           # обработчики команд и пользовательских сценариев
keyboards.py      # Telegram-клавиатуры и меню
services.py       # бизнес-логика, операции с задачами и сводки
db.py             # подключение к SQLite, создание таблиц и запросы
scheduler.py      # периодическая проверка и отправка напоминаний
config.py         # чтение и проверка настроек
requirements.txt  # зависимости Python
.env.example      # шаблон конфигурации
Procfile          # команда запуска для хостинга
runtime.txt       # версия Python для окружения развёртывания
```

## Пример пользовательского сценария

1. Пользователь запускает бота и добавляет учебный предмет.
2. Создаёт работу, указывая её тип, название и дату сдачи.
3. Проверяет задачи по предмету или статусу.
4. Отмечает выполненное задание; статус записывается в базу данных.
5. Получает запланированные напоминания и сводки по предстоящим работам.
